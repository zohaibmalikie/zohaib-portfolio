## B. Implemented improvements and affected files

The public routes and existing visual system are preserved. There are no new packages or database migrations. Unpublished content is kept in the existing bundled format, with CMS-authoritative overrides intact.

- **Canonical and indexing policy:** `lib/url-policy.ts`, `lib/seo.ts`, `lib/indexing.ts`, `sanity/env.ts` normalize origins/canonicals and separate a page's path from an optional canonical override. `app/(site)/blog/[slug]/page.tsx`, service details and project details use that policy.
- **Draft/admin/discovery:** `proxy.ts`, `app/layout.tsx`, `app/(site)/layout.tsx`, `app/studio/[[...tool]]/page.tsx`, `app/not-found.tsx`, both llms route handlers, the humans route, and `app/sitemap.ts` implement the indexing/cache/discovery changes described above.
- **CMS correctness:** `sanity/lib/fetchers.ts` now fetches full project details, supports published-only discovery settings and merges related-service fields. `sanity/lib/queries.ts` projects new fields and handles the known LedStore alias. `lib/project-collections.ts` makes canonical selection deterministic and preserves defined SEO values.
- **Professional positioning:** homepage metadata/schema, `components/sections/hero.tsx`, `components/sections/about.tsx`, `lib/fallback-data.ts`, `lib/service-content.ts`, service hub/detail routes and work routes improve visible targeting and relevant paths to contact. The fallback GitHub link points to the known account instead of the GitHub home page.
- **Editable fields:** `sanity/schemas/siteSettings.ts`, `sanity/schemas/service.ts` and `types/sanity.ts` add professional headline/summary and related-service slugs. `sanity/schemas/seo.ts` describes page-level fields consistently. No CMS publish operation was performed.
- **Archive and related content:** `lib/pagination.ts`, blog archive, work index, `lib/topics.ts` and fetchers enforce relevant, indexable collections and accurate continuation URLs. `lib/llms.ts` recognizes the professional summary where supplied.
- **Work payload:** `app/(site)/work/page.tsx` passes a typed summary projection to `components/project-explorer.tsx`; full case-study content stays on the server.
- **CMS outage handling:** detail reads now distinguish upstream failure from a successful missing-document result when no bundled fallback exists.
- **Structured data:** `lib/json-ld.ts` and `components/json-ld.tsx` fix escaping. The homepage includes ProfilePage linked to the existing Person/WebSite identity. Existing BlogPosting, WebPage, BreadcrumbList, Service and visible FAQ data remain; no rich-result eligibility is promised.
- **Five pending guides:** `content/editorial-articles.json`, `content/blog-enrichment.json`, `content/blog-cover-art.json` and five article-specific files under `public/assets/img/blogs/artwork/`. Details, final image prompts, provenance and asset paths are in `docs/service-buyer-guides-2026-10-20.md` and the cover ledger. No additional batch was created for this audit.
- **Regression prevention:** `tests/seo.test.mjs`, `scripts/audit-seo.mjs`, `package.json`, `AGENTS.md` and `docs/seo-automation.md`. `test:seo` uses Node 22.19+ native TypeScript stripping; `audit:seo` runs against an already running production server. A local release hold prevents routine maintenance from deploying this pending work.

Shared growth and FAQ styles now load from the root layout, removing component-level side-effect imports. Since the footer already included growth styles on every public page, this consolidates existing shared CSS rather than introducing a new design framework or dependency.
